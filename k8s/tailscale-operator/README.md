# Tailscale Operator

The [Tailscale Kubernetes Operator](https://tailscale.com/kb/1236/kubernetes-operator)
(v1.98.9), installed as static manifests rendered from the official Helm chart.
It is the intended mechanism for exposing cluster services over the tailnet with
HTTPS. Existing services still using per-pod Tailscale sidecars are migrated onto
it incrementally.

## Layout

| File | Contents |
|---|---|
| `00-namespace.yml` | `tailscale` namespace |
| `01-sealed-secret.yml` | `operator-oauth` SealedSecret (generated by `seal.sh`, not present until you seal) |
| `02-crds.yml` | Operator CRDs |
| `03-rbac.yml` | ServiceAccounts, ClusterRole/Binding, Roles/Bindings |
| `04-operator.yml` | Operator Deployment + `tailscale` IngressClass |
| `kustomization.yml` | Applies the above in order |
| `seal.sh` | Seals `secret.yml` into `01-sealed-secret.yml` |
| `secret.yml.example` | Template for the OAuth credentials |

## One-time setup

1. In the Tailscale admin console, add `tag:k8s-operator` and `tag:k8s` to your
   tailnet ACL policy, and allow `tag:k8s-operator` to own `tag:k8s`:

   ```jsonc
   "tagOwners": {
     "tag:k8s-operator": [],
     "tag:k8s":          ["tag:k8s-operator"]
   }
   ```

2. Create an [OAuth client](https://login.tailscale.com/admin/settings/oauth)
   with **Devices Core: write** and **Auth Keys: write** scopes, tagged
   `tag:k8s-operator`.

3. Seal the credentials:

   ```bash
   cp secret.yml.example secret.yml
   # edit secret.yml with the OAuth client_id / client_secret
   ./seal.sh
   ```

   This writes `01-sealed-secret.yml`. Commit it; `secret.yml` is gitignored.

## Deploy

```bash
kubectl apply -k k8s/tailscale-operator
```

## Exposing a service (later)

Give any Service a Tailscale HTTPS endpoint with an Ingress:

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: myservice
spec:
  ingressClassName: tailscale
  tls:
    - hosts:
        - myservice          # becomes myservice.<tailnet>.ts.net
  rules:
    - http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: myservice
                port:
                  number: 80
```

## Upgrading

Re-render the chart and overwrite the files:

```bash
helm repo update tailscale
helm template tailscale-operator tailscale/tailscale-operator \
  --version <new-version> --namespace tailscale \
  --show-only templates/connector.yaml --show-only templates/dnsconfig.yaml \
  --show-only templates/proxyclass.yaml --show-only templates/proxygroup.yaml \
  --show-only templates/proxygrouppolicy.yaml --show-only templates/recorder.yaml \
  --show-only templates/tailnet.yaml > 02-crds.yml
helm template tailscale-operator tailscale/tailscale-operator \
  --version <new-version> --namespace tailscale \
  --show-only templates/operator-rbac.yaml --show-only templates/proxy-rbac.yaml > 03-rbac.yml
helm template tailscale-operator tailscale/tailscale-operator \
  --version <new-version> --namespace tailscale \
  --show-only templates/deployment.yaml --show-only templates/ingressclass.yaml > 04-operator.yml
```

The chart does not template the namespace or the OAuth secret, so
`00-namespace.yml` and `01-sealed-secret.yml` are maintained by hand.
